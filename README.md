# Mail Archive — просмотр OST/PST и перенос OST → PST

Бесплатное приложение для Windows 10/11 с русским графическим интерфейсом.
Просмотр работает без Outlook: исходные архивы читает XstReader, только на чтение.
Создание PST требует **классического Outlook для Windows** с настроенным профилем.
Новый Outlook из Microsoft Store COM-автоматизацию не поддерживает.
Платных SDK, подписок, серверов и загрузки писем в облако нет.

## Запуск

Распакуйте `MailArchive-win-x64.zip` и запустите `MailArchive.exe`.
В автономную сборку включён .NET; отдельно устанавливать его не нужно.
Сборка не подписана цифровым сертификатом.

1. При закрытом Outlook сделайте отдельную локальную копию исходного OST/PST.
2. Нажмите **Открыть OST / PST…**, выберите копию, затем папку и письмо.
3. Поиск над списком фильтрует тему, отправителя и получателя **в выбранной папке**.
4. Читайте текст/RTF или текстовое представление HTML. Во второй вкладке доступен исходный HTML.
   Внешние картинки и скрипты не загружаются; вёрстка HTML не отображается.
5. Для обычного файлового вложения выберите его внизу и нажмите **Сохранить вложение…**.
   Вложение сохраняется по вашему выбору и не запускается автоматически.
6. Для OST нажмите **OST → PST…**, задайте **новое** имя файла и прочитайте описание переноса.
   Дождитесь результата. Outlook может показать запрос профиля или доступа к адресным данным.
7. Проверьте JSON-отчёт рядом с результатом и откройте созданный PST в Outlook.

Не открывайте исходный архив в другой программе во время работы. Приложение удерживает его только для чтения,
без разрешения записи другим процессам. Использование отдельной копии особенно важно, если Outlook
при запуске использует этот же OST в своём профиле.

## Что именно конвертируется

Это **восстановление почтовых сообщений**, а не побитовый или полностью эквивалентный перенос MAPI-хранилища.
Приложение читает отключённый OST напрямую, создаёт Unicode PST через установленный Outlook и переносит
иерархию папок, тему, получателей, доступное тело письма, обычные файловые вложения и основные метаданные
отправителя/даты/прочтения. Дерево исходного архива помещается в папку **Импорт OST**.

- Календари, контакты, задачи, правила и другие непочтовые элементы не переносятся.
- Письма с вложенными сообщениями, OLE/ссылочными вложениями и S/MIME пропускаются **целиком** с причиной в отчёте.
- Не гарантируется сохранение всех MAPI-свойств, категорий, цифровых подписей, произвольных пользовательских классов
  и Exchange-адресов. При недоступности Exchange получатели могут остаться неразрешёнными.
- В OST могут отсутствовать несинхронизированные письма, полные тела и вложения. Из отсутствующих данных
  восстановить полный ящик нельзя. Повреждённые/неподдерживаемые варианты формата могут не открыться.
- На большом архиве структура папок и заголовки выбранной папки загружаются в память; конвертация проходит по папкам,
  освобождая обработанные данные. Процесс выполняется в фоне, отдельно от интерфейса.
- Отмена срабатывает между письмами. Блокирующий диалог Outlook необходимо закрыть вручную.

Существующие PST не перезаписываются. Во время переноса используется файл `*.partial.pst` в выходной папке.
После завершения приложение отключает его от Outlook и переименовывает в выбранный результат.
При отмене/фатальной ошибке неполный PST сохраняется отдельно, его путь указан в отчёте.
Ошибки отдельных писем и пропуски показываются отдельно от числа перенесённых писем.
JSON-отчёт содержит пути, темы и причины ошибок; храните его как потенциально конфиденциальные данные.
Временные копии вложений находятся в `%TEMP%/MailArchive-*` и удаляются после письма; после аварийного
завершения приложения оставшиеся временные папки можно удалить вручную.

## Сборка из исходников

Установите .NET SDK 8. В PowerShell из этой папки:

```powershell
.\Build.ps1
# Вариант для 32-разрядной системы:
.\Build.ps1 -Runtime win-x86
```

Архив результата: `dist/MailArchive-win-x64.zip`. Исходный код приложения — `src/MailArchive`.
Сборка поддерживает кросс-компиляцию на Linux; интерфейс и Outlook работают только на Windows.

Приложение находится в корне репозитория. GitHub Actions (`.github/workflows/build.yml`)
проверяет чтение OST/PST на Windows и собирает ZIP с приложением. Тест настоящего переноса через
Outlook запускается отдельно, поскольку на стандартном CI-агенте нет настроенного профиля Outlook.

## Проверки

Загрузите публичные тестовые OST/PST (не личную почту):

```powershell
.\tests\Get-Fixtures.ps1
dotnet run --project tests/MailArchive.Checks -c Release -- tests/fixtures/example-2013.ost tests/fixtures/dist-list.pst
```

Проверяется чтение реальных OST/PST, известное тело письма, неизменность SHA256 исходников,
ошибочный формат, защита имён вложений и запрет перезаписи результата.

Для проверки **создания PST** на Windows с классическим Outlook:

```powershell
dotnet run --project tests/MailArchive.WindowsChecks -c Release -- tests/fixtures/example-2013.ost "$env:TEMP\MailArchive-check-$([guid]::NewGuid()).pst"
```

Эта проверка действительно запускает Outlook, создаёт новый PST, открывает результат независимым reader,
сверяет число перенесённых писем, известное тело письма и SHA256 исходного OST.
Запускайте её в тестовом профиле Outlook. Выходной PST и отчёт остаются для проверки.

В облачной Linux-среде подтверждены сборка приложения и 19 проверок reader/защиты файлов/кодировок.
Запуск Windows-интерфейса и Outlook-конвертация в этой среде **не выполнялись**.
Перед переносом важных данных обязательна проверка на Windows и сравнение результата с исходником.

Лицензии и источник reader: `THIRD-PARTY-NOTICES.md`, `vendor/XstReader/UPSTREAM.md`.
