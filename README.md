# Mail Archive 1.2.0 — OST/PST

Бесплатный просмотрщик OST/PST для Windows 10/11 и перенос писем в PST через **классический Outlook**.
Новый Outlook COM-автоматизацию не поддерживает. Просмотр файлов не требует Outlook.

Готовые сборки: [GitHub Releases](https://github.com/ctaniclab/devops-portfolio/releases).
Публикация новой версии разрешается только после тестов, проверки опубликованного EXE и сканирования Microsoft Defender.
Сборка 1.0.1 ранее получила обнаружение Defender; её EXE больше не распространяются через актуальную ветку.
Сканирование не является гарантией отсутствия любых угроз. Если защита блокирует файл, не отключайте её и не добавляйте исключения.

## Запуск и просмотр

Скачайте EXE из проверенного релиза и запустите. Распаковка и отдельная установка .NET не нужны.
Для подробного HTML-просмотра нужен бесплатный **Microsoft Edge WebView2 Runtime** (обычно уже установлен в Windows).
Если его нет, письмо останется доступно на вкладке «Текст письма»; официальный установщик: https://developer.microsoft.com/microsoft-edge/webview2/.

1. При закрытом Outlook сделайте локальную копию OST/PST и откройте её кнопкой «Открыть OST / PST…».
2. Выберите папку и письмо. Поиск фильтрует тему/отправителя/получателя в выбранной папке.
3. Вкладка «Письмо» показывает HTML и RTF с форматированием, таблицами и доступными встроенными CID-изображениями.
   JavaScript, внешние картинки, переходы по ссылкам и другие сетевые ресурсы письма отключены.
4. Вкладки «Текст письма», «Исходный HTML», «Свойства» дают альтернативное представление и подробные данные.
   Заголовок содержит отправителя, адреса получателей/копий и даты.
5. При открытии PST приложение выбирает заполненную папку, предпочитая «Входящие», а не пустую стандартную папку Outlook.
6. Для файлового вложения выберите его внизу и нажмите «Сохранить вложение…». Файл не запускается автоматически.

Исходный архив открывается только для чтения, без разрешения другим процессам записывать в него.
Используйте копию, поскольку запускаемый Outlook может использовать оригинальный OST своего профиля.

## Конвертация

- **«OST → PST…»** переносит доступные письма и дерево папок всего открытого OST.
- **«Выбранное письмо → PST…»** переносит только выделенное письмо с его файловыми вложениями в отдельный PST.
  Выбор привязан к идентификаторам папки и сообщения, а не к теме письма или номеру строки поиска.
- Нужен установленный классический Outlook с настроенным профилем. Он может запросить доступ к адресным данным.
- Выберите новое имя результата: существующие PST не перезаписываются.
- Письма находятся под **«Перенесённая почта»**. Служебные уровни `Корень - п/я / IPM_SUBTREE` не создаются заново; структура пользовательских папок сохраняется.
- Перед завершением приложение повторно запрашивает количество элементов в папках Outlook и сверяет его с числом сохранённых писем.
  `OutlookReadBackVerified`, `OutputMessagesVerified` и пути заполненных папок `OutputFolders` записываются в отчёт.
  Это проверка через Outlook в той же сессии, а не независимая проверка файла после закрытия процесса Outlook.
- **«Открыть PST в Outlook…»** подключает результат и показывает первую папку с элементами. Если результата ещё нет, можно выбрать ранее созданный PST.
  Повторный импорт не требуется. Если тот же PST открыт в просмотрщике, он освобождается перед подключением к Outlook.
- PST создаётся сразу с выбранным именем. Приложение не переименовывает открытый Outlook файл.
- При отмене/ошибке этот же файл может быть неполным: его путь и результат перечислены в JSON-отчёте.
- Кнопка «Открыть отчёт / журнал…» открывает последний отчёт в Блокноте. В нём есть версия приложения, режим,
  этапы ошибок, число перенесённых/пропущенных/неудачных писем и предупреждения метаданных.

Если старый PST версии 1.1.0 выглядит пустым, раскройте `Импорт OST → Корень - п/я → IPM_SUBTREE → Входящие`
(названия зависят от языка архива) либо выберите этот PST кнопкой «Открыть PST в Outlook…» новой версии.
В Outlook можно включить полный список папок сочетанием Ctrl+6 и проверить, что в представлении нет фильтров.

Пропуск `IPM.Contact` означает контакт, а не потерянное письмо. Такие пропуски теперь объясняются отдельно в результате.
Предупреждение о поле `007D` означает отказ записать служебные транспортные заголовки: само письмо переносится.

Это восстановление писем, а не полная копия MAPI-хранилища. Сохраняйте исходный архив до проверки результата.
RTF переводится в HTML через RtfPipe с сохранением доступного форматирования; некоторые особенности вёрстки могут отличаться.
Отказы Outlook записать необязательное поле (включая отображаемые как UnauthorizedAccessException) фиксируются отдельно,
а не удаляют письмо. Ошибка тела, вложения или сохранения по-прежнему считается ошибкой переноса.
Контакты, календари, задачи, правила и непочтовые классы не импортируются. Вложенные сообщения, OLE/ссылочные вложения,
S/MIME пропускаются с причиной в отчёте. Exchange-адреса могут остаться неразрешёнными без доступа к Exchange.
Из отсутствующих локально данных OST нельзя восстановить несинхронизированные письма или вложения.

Встроенные изображения предпросмотра ограничены по размеру; большие/недоступные картинки заменяются подписью.
Временные копии вложений конвертации хранятся в `%TEMP%/MailArchive-*` и удаляются после письма.
После аварийного завершения оставшиеся временные папки можно удалить вручную.
Отчёты содержат пути, темы и диагностические сведения: удалите личные данные перед передачей отчёта.

## Разработка и проверки

Установите .NET SDK 8. Из корня репозитория в PowerShell:

```powershell
.\tests\Get-Fixtures.ps1
dotnet run --project tests/MailArchive.Checks -c Release -- tests/fixtures/example-2013.ost tests/fixtures/dist-list.pst
.\Build.ps1
```

Обычная сборка: `src/MailArchive/MailArchive.csproj`. Автономная публикация без сжатия содержимого EXE — `dist/win-x64/MailArchive.exe`.
ZIP со всеми сопроводительными лицензиями — `dist/MailArchive-win-x64.zip`.
Сборка на Linux поддерживается; интерфейс и Outlook работают только на Windows.

Проверка опубликованного EXE на Windows без Outlook:

```powershell
.\dist\win-x64\MailArchive.exe --self-check-output "$env:TEMP\mailarchive-preview.json"
```

Она открывает главное окно с иллюстрацией, проверяет загрузку ресурса и скруглённый шаблон кнопок, сохраняет снимок пустого интерфейса,
затем открывает WebView2, сверяет содержимое таблицы и кириллицу, проверяет отключение скриптов и записывает результат.
Снимок `ui-preview.png` прикладывается к проверенному релизу и не содержит пользовательской почты.
Полный тест Outlook (создание PST, повторное чтение результата, затем перенос ровно одного выбранного письма):

```powershell
dotnet run --project tests/MailArchive.WindowsChecks -c Release -- tests/fixtures/example-2013.ost "$env:TEMP\MailArchive-check-$([guid]::NewGuid()).pst"
```

Запускайте его в тестовом профиле Outlook, не на рабочем оригинале архива.
На стандартном CI нет профиля Outlook, поэтому этот интеграционный тест только компилируется; реальная автоматизация там не заявляется проверенной.
GitHub Actions выполняет проверки reader, собирает EXE, сканирует его Defender, запускает self-check и лишь затем публикует релиз.
Если Defender недоступен или проверка не завершилась, публикация блокируется.
