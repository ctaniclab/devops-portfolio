# Mail Archive 1.5.0 — OST / PST / MSG

Бесплатное Windows-приложение для просмотра OST/PST и сохранения выбранных сообщений в PST или отдельные Unicode MSG.
Для обоих вариантов конвертации нужен установленный **классический Outlook** с настроенным профилем.
Для просмотра Outlook не требуется; для форматированного просмотра нужен бесплатный Microsoft Edge WebView2 Runtime.

Готовые EXE без распаковки и установки .NET: [GitHub Releases](https://github.com/ctaniclab/OST2PST_Converter/releases).
Релиз публикуется только после тестов, проверки готового EXE на Windows и Microsoft Defender.
Старая версия 1.0.1 получала обнаружение Defender; это не объявлено ложным срабатыванием. Если защита блокирует файл,
не отключайте её и не добавляйте исключения. Отчёт сканирования и SHA256 новой сборки находятся в релизе.

## Просмотр

1. Сделайте локальную копию OST/PST при закрытом Outlook.
2. На вкладке **«Просмотр архива»** нажмите **«Открыть OST / PST…»**.
3. Выберите папку слева. В обычном режиме показаны заполненные почтовые папки и необходимые родительские уровни.
   Реальное содержимое таблиц проверяется при открытии: устаревший нулевой счётчик OST не скрывает почту, включая `IPF.Imap`.
   Контакты/календари и служебные ветки доступны через **«Показать служебные»**.
4. Выделите письмо и нажмите **«Читать письмо»**, дважды щёлкните по строке или нажмите Enter.
   Письмо открывается отдельным окном. Разделитель панелей больше не может скрыть тело письма.
5. В окне доступны форматированное письмо, текст, HTML, свойства, получатели/даты и сохранение файловых вложений.
   Кнопка **«Конвертировать это письмо…»** открывает общий мастер с заранее отмеченным сообщением.

Исходник открывается только для чтения; другие процессы не могут писать в него, пока он открыт приложением.
HTML не запускает JavaScript, не загружает внешние ресурсы и не открывает ссылки. Доступные CID-картинки встраиваются локально,
крупные/неподдерживаемые изображения заменяются подписью. Файловые вложения не запускаются автоматически.
Если WebView2 отсутствует, используйте вкладку «Текст»; официальный Runtime: https://developer.microsoft.com/microsoft-edge/webview2/.

## Выбор писем и формата

1. Нажмите **«Конвертировать…»** в просмотре или на вкладке **«Конвертация»**.
2. Отметьте галочками несколько сообщений либо нажмите **«Выбрать все»**. Поиск работает по теме, отправителю и папке;
   «Выбрать найденные» добавляет к выбору текущие результаты поиска, «Снять выделение» очищает весь выбор.
3. Нажмите **«Далее: выбрать формат»** и выберите:
   - **PST** — один новый архив с выбранными письмами и необходимой структурой папок;
   - **MSG** — отдельный `.msg` на каждое выбранное сообщение с его файловыми вложениями.
4. Укажите имя нового PST либо родительскую папку MSG. Для MSG создаётся папка с именем исходного OST/PST; при совпадении добавляется `(2)`, `(3)` и т. д.
   Внутри сохраняются исходные папки и подпапки, например `имя архива/Входящие/Работа/письмо.msg`.
   В PST папки лежат непосредственно под именем выходного архива, без дополнительной «Перенесённой почты».
   Имена MSG содержат безопасную тему и идентификаторы: одинаковые темы не перезаписывают друг друга.
5. Для PST используйте кнопку **«Открыть PST в Outlook…»** в шаге 3. Мастер импорта Outlook не требуется: PST подключается
   отдельным архивом, сразу открывается заполненная папка, в первую очередь «Входящие».
   Для MSG нажмите **«Открыть папку MSG…»** и открывайте письма обычным двойным щелчком.

Приложение ничего не отправляет и не импортирует в серверный почтовый ящик. MSG создаются через SaveAs без Save в личные
«Черновики». Существующие PST и MSG не перезаписываются. PST не переименовывается, пока его может удерживать Outlook.
Контакты (`IPM.Contact`), календарь, задачи, S/MIME, OLE/ссылочные вложения и вложенные MAPI-сообщения не конвертируются;
причины перечисляются в отчёте. Обычный прикреплённый файл `.msg` остаётся файловым вложением.
Пустые папки не создаются. Журналы синхронизации и другие известные служебные ветки по умолчанию исключены;
их можно включить в дополнительных параметрах. Стандартные папки, которые создаёт сам Outlook для PST, могут оставаться.

## Проверка содержимого и старые пустые результаты

PST и MSG используют один путь подготовки: временное письмо сохраняется через `SaveAs(..., olMSGUnicode)`,
заново открывается через `OpenSharedItem` и проверяется. Новый MailItem не сохраняется через `Save()` в папку профиля.
Для PST проверенный MSG явно переносится через `Move` в выбранную папку архива; используется **возвращённый** объект
с новым EntryID, сверяются фактические родительская папка и StoreID. Затем письмо заново открывается по этим идентификаторам.
Это устраняет использование идентификатора письма из другого хранилища при проверке PST (`0x80040107`).

- Содержимое MSG проверяется до переноса, содержимое PST — после переноса и повторного открытия;
- сверяются тема, сохранение всех символов текста в исходном порядке (с допуском пробелов/нумерации Word), число получателей,
  наличие изображения в письме без текста и SHA256 всех файловых вложений;
- для PST дополнительно сверяется число элементов по папкам. Пустой архив не получает отметку об успешной проверке;
- Для MSG Outlook пишет короткий временный путь; после закрытия COM проверенный файл переносится в исходную иерархию без перезаписи.
  Недопустимые в Windows символы в именах папок заменяются, совпадающие имена получают суффикс; папки не сливаются;
- защищённые транспортные заголовки `007D` и флаги очереди отправки не перезаписываются через Outlook;
- JSON-отчёт содержит точный этап, например `MoveToPst`, `VerifyPstLocation`, `ReopenPstMessage`, `VerifyPstContent`,
  и код исключения/HRESULT. Ошибка повторного открытия не маскируется поиском в другом хранилище.

Пустой или неполный элемент не считается успешно перенесённым письмом. Успешный счётчик увеличивается после проверки.
Это проверка через Outlook, а не независимая проверка PST другим движком после закрытия процесса Outlook.
Она не гарантирует сохранение всех MAPI-свойств, подписей, правил, категорий, флагов и особенностей вёрстки RTF/HTML.
Состояние черновика восстанавливается в закрытом MSG; полученные письма не помечаются новыми черновиками.

Если старый PST уже содержит пустые элементы, повторно создайте результат из сохранённого OST новой версией.
Повторное открытие старого файла не восстанавливает отсутствующее в нём содержимое. Исходник сохраняйте до проверки результата.
При отмене/ошибке неполный результат и JSON-отчёт сохраняются, приложение не подменяет их успешным итогом.
Отчёт содержит режим, выбранные идентификаторы, формат, число проверенных писем, исключённые служебные ветки и причины ошибок.
Отчёты могут содержать пути/темы: удалите личные данные перед передачей. Пользовательские письма никуда не отправляются.

## Исходные даты сообщений

Даты получения и отправки сохраняются в UTC в фиксированных свойствах закрытого временного MSG до его открытия/переноса
через Outlook. Состояние полученного письма/черновика восстанавливается там же; флаги очереди отправки и уведомлений удаляются.
Прямая запись этих полей через PropertyAccessor больше не используется. После открытия MSG и после переноса в PST даты
сверяются с исходными; несовпадение делает письмо ошибкой переноса. DatesVerified и MessagesWithoutSourceDates есть в отчёте.
В просмотре даты отображаются в местном часовом поясе. Старые результаты с подменённой датой нужно пересоздать из исходника.
Иконка №4 встроена в EXE и окна. Лицензии и ссылки на исходники библиотек доступны по кнопке ℹ даже в одиночном EXE.

## Процент и время конвертации

Рядом с полосой прогресса отображаются процент, прошедшее время и приблизительное оставшееся время.
Используется точное число отмеченных сообщений, включая «Выбрать все». Время запуска Outlook не считается
скоростью обработки письма: прогноз появляется после первых двух сообщений и плавно адаптируется к скорости.
Во время длительной задержки вместо устаревшего нулевого таймера выводится «Оценка времени уточняется».
Закрытие и проверка PST показаны отдельным этапом на 99%; 100% появляется только после успешного завершения.
Оценка приблизительная: крупные вложения, диск и Outlook влияют на скорость. При неизвестном числе сообщений API
использует неопределённый прогресс, не выдумывая процент. В обычном мастере число выбранных сообщений известно.

## Темы, HDR и прокрутка

Доступны 11 вариантов оформления: системная, светлая «бумага», тёмная, прежняя сиреневая классическая,
Liquid Glass, прозрачная, космос, океан, аврора, неон и терминал. Отличаются фон, геометрия панелей и кнопок,
шрифт, границы и материалы. «Терминал» использует Consolas и прямые линии; светлая — тёплую бумагу и Georgia в заголовке;
«Аврора» — оригинальный векторный лунный лес; «Неон» — перспективную сетку; «Океан» — морские волны.

**Liquid Glass** — светлые глянцевые панели, крупные капсулы и системное размытие. **Прозрачная** — тёмное окно с фоном
рабочего стола. Для реального Desktop Acrylic нужна Windows 11 22H2+ с включёнными эффектами прозрачности.
Флажок «Эффекты стекла» позволяет отключить размытие отдельно от совместимости HDR. На старой Windows,
при отключённой прозрачности, высокой контрастности или отказе DWM приложение использует читаемый непрозрачный фон
и показывает причину под переключателем темы. Windows может упрощать материал при неактивном окне/энергосбережении.
Настройки Windows приложение не меняет. Прежний выбор «Стекло» автоматически заменяется на Liquid Glass.

Выбор сохраняется локально, смена темы не сбрасывает открытый архив. Заголовки, текст и рамки всех трёх окон следуют теме
на Windows 11; на Windows 10 применяется системный тёмный/светлый заголовок. Системные кнопки и изменение размеров
остаются стандартными. Контраст текста, выбранных строк и кнопок проверяется для каждой палитры, включая прозрачные слои.
Источники вдохновения и реализация эффектов: [docs/THEMES.md](docs/THEMES.md).

Полосы прокрутки вертикальные и горизонтальные, с округлым заметным ползунком, поддерживают колёсико, прокрутку страниц и перетаскивание.
Встроенный браузер имеет такие же округлые полосы. «Светлый фон письма» помогает читать исходные HTML-письма с собственными цветами.

**«Совместимость с HDR»** по умолчанию включает программную отрисовку WPF и браузера, sRGB-профиль предпросмотра,
сглаживание текста в градациях серого. Это режим совместимости SDR-интерфейса с HDR/драйвером, а не собственный HDR-рендерер.
Настройки дисплея Windows не меняются. Режим можно отключить; для нового режима браузера заново откройте окно письма.
Добавлена Per-Monitor V2 DPI awareness. Физический HDR-монитор на CI отсутствует — аппаратная совместимость не подтверждена.

## Разработка

.NET SDK 8; из корня репозитория в PowerShell:

```powershell
.\tests\Get-Fixtures.ps1
dotnet run --project tests/MailArchive.Checks -c Release -- tests/fixtures/example-2013.ost tests/fixtures/dist-list.pst
.\Build.ps1
```

Готовый автономный EXE: `dist/win-x64/MailArchive.exe`; ZIP с сопроводительными лицензиями: `dist/MailArchive-win-x64.zip`.
Сборка и переносимые проверки работают на Linux; WPF/Outlook — только на Windows.

Проверка готового EXE без Outlook (главное окно, все темы, чтение HTML/кириллицы, обе полосы прокрутки,
выбор двух сообщений/всех, переход к выбору PST/MSG):

```powershell
.\dist\win-x64\MailArchive.exe --self-check-output "$env:TEMP\mailarchive-check.json" --fixture tests/fixtures/example-2013.ost
```

Windows self-check делает снимки интерфейса с публичным тестовым архивом/синтетическим письмом. Пользовательская почта не загружается.
На тестовом профиле классического Outlook можно выполнить интеграционный тест в **трёх проходах**: полный PST,
PST одного письма, PST двух выбранных писем и два MSG. Выходные файлы каждого прохода имеют новые имена,
проверяются содержимое/счётчики, идентификаторы, чтение PST независимым XstReader и неизменность SHA256 исходника:

```powershell
dotnet run --project tests/MailArchive.WindowsChecks -c Release -- tests/fixtures/example-2013.ost "$env:TEMP\MailArchive-check-$([guid]::NewGuid()).pst"
```

На стандартном CI Outlook не настроен: этот тест только компилируется. Конвертация на пользовательском Outlook и реальный HDR-монитор
не заявляются проверенными. Проверки: [VERIFICATION.md](VERIFICATION.md). Лицензии: [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md).
