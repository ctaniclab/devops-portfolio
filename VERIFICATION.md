# Проверка сборки

Выполнено в Linux:

- .NET SDK 8.0.426: Release-сборка Windows WPF-приложения.
- Автономная публикация `win-x64`, один EXE со встроенным .NET.
- 36 проверок `MailArchive.Checks`, все прошли.
- Регрессионный тест воспроизвёл неполную распаковку OST-блока на прежнем reader; после исправления проходит.
- Проверены все три уровня zlib, фрагментированные чтения, отказ на испорченной контрольной сумме,
  обрезанном блоке и неверной объявленной длине.
- Проверены пустые темы, разреженная bitmap таблицы, 64-битные BID и нулевой устаревший счётчик писем.
- Проверена политика продолжения после ошибки папки и учёт отказа Outlook записать необязательное поле через имитацию COMException.
- Настоящий OST: 40 папок, 3 элемента, 3 тела; известное тестовое письмо прочитано корректно.
- Настоящий PST: 18 папок, 4 элемента, 1 тело (остальные элементы — не обычные письма).
- SHA256 обоих исходных тестовых архивов после чтения не изменился.
- Windows-тест конвертации скомпилирован.

Не выполнялись: запуск WPF на Windows, реальная автоматизация Outlook, проверка полученного через Outlook PST,
запуск PowerShell Build.ps1. Для сборки применена эквивалентная команда `dotnet publish`.
Тест `MailArchive.WindowsChecks` предназначен для проверки Outlook на целевой Windows-машине.
Проверенное чтение архива не подтверждает работоспособность Outlook-конвертации в конкретном профиле.
Пользовательский OST, на котором возник сбой во «Входящих», не предоставлен; его успешное чтение и
конвертация пока не подтверждены. Версия 1.0.1 сохраняет подробные исключения в отчёте/локальном журнале.
